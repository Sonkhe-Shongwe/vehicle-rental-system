## Honest limitation and next release gate

The synthetic QT_SCALE_FACTOR runs prove that Qt rendered the chosen views and emitted appropriately scaled image buffers without failing runtime assertions. **They do not prove** actual Windows monitor scaling is visually excellent, text is not clipped, keyboard focus is accessible, or a human operator can complete a real GUI workflow.

Do **not** merge Draft [PR #4](https://github.com/Sonkhe-Shongwe/vehicle-rental-system/pull/4) merely because these checks passed. A human must still:
1. Open the review branch in **Qt Creator on Windows using a new disposable clone**.
2. Verify all screens with mouse and keyboard at standard, 125% and 150% *actual* display scaling.
3. Create/rent/restart/return/archive/delete on fictional data, including duplicate and forbidden-action cases; confirm dialogs and persisted files.
4. Review photographic quality and the final aesthetic; approve release explicitly.
