## Purpose and exact native implementation

[P6-L acceptance proposal](P6_L_NINE_CRITERION_ACCEPTANCE_REVIEW_PACK_2026-11-02.md) identified that the individually passing P6 operator workflows did not yet prove a **single connected create → book → return → archive → permitted delete → remove → fully reopen** journey in real Qt Quick, across independent executables. P6-M adds **two real native CTests**, `rental_studio_p6_integrated_wide` and `rental_studio_p6_integrated_compact`. Each CTest launches **three independent Qt GUI executable processes** with its own allowlisted fictional workspace, on logical **1500×860** or **1280×720**.

1. **Native process 1, create and book:** start with exactly the SHA-pinned `demo/vehicles.txt` and `demo/rentals.txt` fictional fixtures, and verify 5 Fleet / 4 available / 1 active / 1 returned. Use actual keyboard-driven QML Add Car to commit fictional **C004, Demo Motors Orion, R420/day**, then the Fleet **Book selected vehicle** button to open the real guided Rentals dialog, inspect **R840 for 2 days**, enter fixed synthetic contact **Fictional Journey / 0000000000** and confirm **R003**. Assert post-commit C++ active count 2, Fleet occupancy 4/6, on-disk changed ledger and a rejected duplicate C004 quote without further write.
2. **Native process 2, return and remove:** before creating a `RentalSystem`, validate the **exact stored fictional vehicle/rental lines**, test marker, filenames, SHA-pinned originals, symlink disallowlist, file size bound, and serialization dates. Reopen the independent Qt executable from that real saved ledger. Use keyboard-driven **vehicle-ID return lookup** (`c004`) to select R003; confirm through a **separate QML Return dialog**. The Active-only filter correctly hides the returned record, so an explicit read-only rental-ID lookup restores the historical selection. Verify actual return date and record-reference guard, archive via real QML modal, reject the wrong `DELETE R001` phrase with byte-stable ledger, then confirm `DELETE R003` in disposable fiction and remove no-longer-referenced C004 with exact `REMOVE C004`. Check all reconstructed Fleet/Rentals counts and no accidental deletion of original R001/R002.
3. **Native process 3, independent reopen:** verify the stored Fleet and rental ledgers contain **exactly the original fictional records** (the transactional addition is now legitimately removed); Overview says **4 available and 1 active**, shows real R001 and read-only recent contracts, Rentals History still resolves original returned R002 and its purpose-limited selected-contract details, Fleet still guards active reference C002 and historical reference C001. Capture real native final screenshot per size. Verify original SHA-pinned source fixtures are still byte-for-byte unchanged.

**Strict security and scope:** Only the CI parent creates `rental-studio-p6-integrated-XXXXXX` under temporary storage. Child stages are allowlisted exclusively in that test root, with a distinct stage-specific marker derived from exact committed fictional hashes, no symlinks, no arbitrary command-line data directory and explicit saved-record allowlists. No actual customer PII is printed; failure diagnostics compare **row indices, lengths and truncated SHA256 hashes only**. The private temporary folder is deleted after tests. These are separate from earlier P6-E synthetic child flags and do not change them.
