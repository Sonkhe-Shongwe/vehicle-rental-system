## A. Actual source observations: do not conflate with proposals

| S01 | `rentalsystem.cpp::RentalSystem` uses `QFileInfo(__FILE__).absolutePath()` as default and `vehicles.txt`/`rentals.txt`; P2/P5 supply narrow disposable or fixed fictional-only directories | Source-adjacent legacy paths are not a supported commercial storage location; normal Qt app cannot be enabled for real contacts | Explicit, isolated user-app-local data root only after safety approval; no arbitrary CLI path and no implicit legacy auto-import |
| S02 | `RentalStorage` exposes per-path `read` and `writeAtomic`; `FileRentalStorage` uses `QSaveFile` per independent text file | Each individual replacement is atomic, but there is **no joint two-file transaction** or crash-atomic multi-step operation | Design one transactional storage boundary for Fleet/rental operations, with failure injection and durable restart |

| S04 | `generateNextVehicleId` and `generateNextRentalId` compute `max(existing records)+1`; `removeVehicle` and `deleteArchivedRental` can permanently erase disposable records | Deleted high-number IDs could later be reused. ## B. Legacy input formats evidenced by code

- Vehicle record: seven pipe-separated fields, **Car/Motorcycle | ID | brand | model | decimal daily rate | rented flag 0/1 | doors/engine cc**. Vehicle rates are legacy 2-decimal strings. File format does not include retired state, immutable ID-sequence ledger or schema version.
- New rental record: **13 fields**, `Rental|ID|customer|phone|vehicle ID|start YYYY-MM-DD|expected YYYY-MM-DD|actual date or empty|days|rate|total|returned 0/1|archived 0/1`.
- Older rental record: **14 fields** with extra driver's-licence column at position 5 (one-indexed) before vehicle ID; all date/amount/flags shift one column. This field is **not** surfaced in current Qt Quick roles.
- Dates are parsed as Qt ISO `QDate`; actual date may be absent. Returned + absent actual date is currently synthesized for legacy display, not evidenced as the true date.
- Legacy loader skips many invalid lines and no index/foreign-key enforcement exists; **import may not reuse this permissive loader as a data-validation oracle**.

## C. P7 safety priorities, highest first

1. **No silent data loss** (unparseable lines, duplicate IDs, conflicting active rentals, missing active vehicle, 14-field licence, historical missing actual date).
2. **No identity reuse**, including deleted highest-number C/M/R and case-insensitive duplicates.
3. **Exact monetary semantics** in integral cents; reject overflow, noncanonical decimal/currency strings and mismatched totals before migration.
4. **One database transaction** for business state transitions, documented rollback and durable independent-process recovery.
5. **Commercial retirement/archive policy**, historical foreign keys and immutability expectations, not irreversible hard delete.
6. **Backup-and-restore proof, repair refusal and privacy** before any general-purpose storage activation.
