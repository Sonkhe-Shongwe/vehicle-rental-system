## One executable physical-session procedure

1. **Extract the full official Windows portable QA ZIP**, never run from inside the archive and do not use administrator privileges. Only the bundled fictional `demo/vehicles.txt` and `demo/rentals.txt` may be used. Inspect `SOURCE_COMMIT.txt` with the PR-merge identity note above. Do not import real rental data.
2. **Automated on-device smoke:** from extracted root, review then run `.\Verify-P2-Windows.ps1 -VerifyOnly` and `.\Verify-P4-Windows.ps1 -VerifyOnly` in PowerShell. These scripts log to `acceptance-evidence`, check fixture SHA-256 and produce packaged process results. They do **not** change OS settings, certify Narrator or mark physical scale PASS. If unsigned scripts are disallowed, follow the user's local security policy; never globally weaken execution policy.
3. **Actual Qt application:** launch `RentalStudioP2Review.exe` and inspect Overview, Fleet Gallery/Table/selected Inspector/filter/sort and Rentals search/filter, New Rental/Return/Archive dialogs. Test mouse and keyboard, real Tab/Shift+Tab/Space/Enter/arrows/Escape, focus restoration, scroll and text legibility. These interactions must be carried out on the owner's Windows machine.
4. **Actual Windows scaling:** start with the previously observed **1920 × 1080, 150% recommended** Settings baseline; check real current app, then 100%/125% only where supported and safe. At 150%, an approximately 1280×720 **logical** desktop before taskbar will not fit a 1500×860 logical app window; do not misdiagnose that expected desktop limit as a viewport rendering defect. Record window size, scale and app-only screenshots, separately for each tested condition.
5. **Actual Windows Narrator:** if supported, toggle with **Win + Ctrl + Enter**; listen for meaningful Overview/Fleet/Rentals names and checked state, Gallery/Table choice, rental filter selected state, row due/status/amount, labeled form fields and confirmation initial Cancel focus, no trapped Tab route. Record specific spoken output, not merely a screenshot.
6. **Local Qt Creator/MinGW gate:** if the owner has the source checkout, record exact local SHA, Qt Creator and kit/compiler version, build the current Qt Quick target in a fresh directory and attach CTest output. The **hosted MSVC portable executable cannot satisfy this separately required gate**.
7. **Photos and whole-product design:** review actual cohesive imagery and licensed model accuracy, not just image-source research; give explicit aesthetic verdict. If photos are missing, retain P1 image criterion as OPEN. Confirm no customer names/phones/license data are exposed by public history roles.
8. **Record each item independently:** PASS, FAIL or NOT TESTED, with observed values and source/kit evidence, then request formal owner decisions. Keep raw system/account details private; share only sanitized application screenshots and reports.
